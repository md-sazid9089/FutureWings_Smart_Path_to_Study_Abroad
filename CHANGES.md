# FutureWings — Premium Unlock Fix & Hardening

## Bug Fixed
SOP Testing page remained locked after premium purchase while AI Assistant unlocked correctly.

## Root Cause
`PaymentSuccess.jsx` called `utils/syncPremiumStatus` which only updated `localStorage`. `PremiumFeatureWrapper` reads from AuthContext (React state), not localStorage, so SOP page never re-rendered as unlocked.

## Files Changed

### Frontend
- `src/pages/PaymentSuccess.jsx`
  - Replaced utility `syncPremiumStatus` import with `useAuth().syncPremiumStatus()`
  - Now updates React AuthContext state after payment, triggering re-render

- `src/components/PremiumFeatureWrapper.jsx`
  - Added `window` event listener for `userUpdated` as a fallback re-render trigger

- `src/layouts/AppLayout.jsx`
  - Replaced utility import with `useAuth().syncPremiumStatus()` and uses it on load/storage events

- `src/pages/Signup.jsx`
  - Replaced utility import with `useAuth().syncPremiumStatus()` (syncs context after signup)

### Backend
- `src/middleware/auth.js`
  - Added `requirePremium` middleware
  - Checks `isPremium` and `premiumExpiryDate` from DB
  - Returns 403 if not premium or expired

- `src/routes/ai-assistant.js`
  - Added `requirePremium` to `POST /chat` and `POST /sop-review`

- `src/routes/payments.js`
  - Webhook now reads `session.metadata.featureType` instead of always granting `PREMIUM_BUNDLE`
  - Adjusted webhook handler to handle parsed or raw bodies when possible (improved robustness)

### Dev/Test Scripts Added
- `backend/scripts/activate_demo.js`
- `backend/scripts/activate_demo_custom.js`
- `backend/scripts/deactivate_demo.js`
- `backend/scripts/check_demo_user.js`
